架构设计 ​

前端架构设计原则 ​

如何设计一个可扩展、可维护的前端架构 ​

  • 分层架构（UI 层、业务逻辑层、数据层）
  • 模块化与组件化设计（微前端、Monorepo）
  • 状态管理规范化（Redux、Pinia 或 Context API 的选型逻辑）
  • 统一代码规范（ESLint/Prettier）和文档驱动开发
  • 性能与安全基线（如资源加载策略、CSP 配置）

如何平衡技术选型的先进性与团队落地成本 ​

  • 评估团队技术栈熟悉度与学习曲线
  • 小规模试点验证稳定性，渐进式迁移
  • 长期维护成本（如社区活跃度、升级兼容性）
  • 结合业务场景（如高实时性选 WebSocket，SSR 选 Next.js）

性能优化与监控 ​

如何系统性地优化前端性能？列举关键指标和工具 ​

  • 核心指标：LCP、FID、CLS（Web Vitals）、首屏时间
  • 工具链：Lighthouse、Webpack Bundle Analyzer、Sentry
  • 优化手段：
    • 代码分割（Dynamic Import）
    • 资源压缩（Brotli）、CDN 加速、HTTP/2
    • 缓存策略（Service Worker、LocalStorage）
    • 渲染优化（Virtual List、GPU 加速）

如何设计前端错误监控体系 ​

  • 异常捕获（Window.onerror、Promise Catch、React Error Boundary）
  • 日志分类（JS Error、API Error、资源加载失败）
  • 上下文信息（用户设备、网络状态、操作路径）
  • 报警阈值与自动化归因（Sentry + Slack/钉钉通知）

工程化与 DevOps ​

如何设计前端 CI/CD 流程 ​

  • 代码检查（ESLint、单元测试）
  • 多环境构建（区分 dev/test/prod）
  • 自动化部署（Jenkins/GitHub Actions/GitLab CI + Docker）
  • 灰度发布与回滚机制

如何管理大型项目的依赖和构建速度 ​

  • Monorepo 方案（pnpm/Nx/Turborepo）
  • 缓存优化（Webpack5 Persistent Cache、Vite 增量编译）
  • 依赖分析（depcheck）与按需加载

框架与生态 ​

React/Vue/Angular 的技术选型逻辑是什么 ​

  • React：生态丰富（Next.js、AntD）、灵活性强，适合复杂应用
  • Vue：渐进式框架、上手快，适合中小型项目
  • Angular：企业级全栈方案，适合强类型团队
  • 选型需考虑团队能力、社区支持、长期维护性

微前端落地方案及踩坑经验 ​

  • 方案对比（qiankun/Module Federation/Web Components）
  • 子应用隔离（CSS/JS 沙箱、通信机制）
  • 统一路由与状态管理
  • 构建部署独立性与版本控制

架构师软技能 ​

如何推动团队技术升级并保证平稳迁移 ​

  • 技术提案文档（RFC 流程）
  • 渐进式重构（新功能试用 + 旧系统兼容层）
  • 培训与知识共享（内部 Workshop、代码评审）

如何处理遗留系统的技术债务 ​

  • 债务评估（代码质量、文档缺失、安全隐患）
  • 优先级排序（高影响低成本的先修复）
  • 增量重构（Feature Toggle、防腐层设计）

系统设计题 ​

设计一个高并发场景的实时数据仪表盘 ​

  • 数据推送（WebSocket + 降级为轮询）
  • 前端缓存与防抖（避免频繁渲染）
  • 可视化优化（Canvas/WebGL 渲染、数据采样）
  • 服务端聚合（减少传输数据量）
